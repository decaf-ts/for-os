# Vendored `tray-icon-node` — provenance and build notes

This directory is a source copy of [`nglmercer/tray-icon-node`](https://github.com/nglmercer/tray-icon-node),
vendored so the Rust implementation can be audited in this repository and the
native addon can be built from that audited source instead of consuming the
published npm tarball.

## for-os adaptation

This copy is maintained by `@decaf-ts/for-os`. The system-tray runtime is
unchanged from the upstream implementation; the notification bridge was
located in with-ai at `with-ai/vendor/tray-icon-node/src/lib.rs` (the
`show_notification`, `show_appointment_notification`, and
`poll_notification_actions` functions) and is ported here with these additions:

- `NotificationAction` and `show_notification_with_actions(title, body,
  actions, timeoutMs)` let JavaScript supply arbitrary notification buttons.
- `timeout_ms` is accepted by every notification entry point. Linux passes it
  to `notify-send --expire-time`; Windows uses it as the balloon-tip timeout;
  macOS uses the system dismissal policy.
- Linux notifications that have actions now pass `--wait`, so the activated
  action id is actually captured and returned by
  `poll_notification_actions()`. The with-ai version did not wait and therefore
  could not observe button activations.
- `show_appointment_notification` normalizes the reserved `default` action to
  `see` while keeping the `accept` and `see` ids.
- Rust tests cover the notification argument contract (timer, actions, wait)
  in addition to the upstream conversion tests.

The TypeScript layer (`src/`) adds runtime icon switching (`TrayIcon.setIcon`
accepts paths, bytes, base64, and raw RGBA), typed menu callbacks, notification
timers, and JavaScript action mapping. The vendored package name and NAPI
surface stay compatible with the upstream loader.

## Local deviations from upstream packaging

`package.json` differs from the published tarball in exactly these ways:

- `"type": "commonjs"` — the NAPI-RS loader in `index.js` is CommonJS. Upstream
  publishes it inside an ESM package, which required a runtime post-install
  patch in the previous dependency-based implementation. Because this copy is
  under our control, the correct module type is declared directly and the patch
  is gone.
- The unused `bun` peer dependency and `@napi-rs/cli`/`@types/bun`/`typescript`
  dev dependencies are removed. The build uses `cargo` directly (see below) and
  does not install a NAPI CLI from npm.
- The `build` script points at this repository's
  `scripts/for-os-build.mjs`.

The Rust tray runtime and `Cargo.toml` retain the upstream implementation.
`src/common.rs` adds a `#[cfg(test)]` module that verifies mouse-button/state
and rectangle conversions. `src/lib.rs` adds the for-os desktop-notification
bridge: Linux `notify-send`, macOS `osascript`, and a Windows notification-area
balloon via PowerShell. This bridge adds no Cargo dependency. `Cargo.lock` is
new: upstream git-ignores it, but this repository commits it so the cargo
dependency closure is auditable and reproducible.

## Build path: build at install from this source

Decision: **build the native addon at install time from this vendored source**.
No prebuilt binary is downloaded or trusted.

- `npm run for-os:init` installs `cactus-needle` and `uiohook-napi`, then runs
  `scripts/for-os-install.mjs`, which verifies this tree against
  `source-manifest.json`, builds `tray-icon-node.<platform>.node` with cargo when
  needed, and materializes a verified copy under `node_modules/tray-icon-node`.
- `npm run for-os:build` builds explicitly and fails when the toolchain is
  missing.
- `npm run for-os:install:required` requires the build to succeed and then
  materializes the addon into `node_modules/tray-icon-node`.
- If the Rust/C toolchain or the platform GUI headers are unavailable,
  `for-os:init` warns and installs the package without a binary; the tray then
  degrades to the existing single-notice no-tray behavior while dictation keeps
  working.
- `native supply-chain workflow` builds the vendored crate on Linux, macOS, and
  Windows runners to prove the source compiles, and scans `Cargo.lock` for
  known-vulnerable crates.

### Prerequisites for a native build

Install Rust stable for the current user with rustup. This installs `rustup`,
`cargo`, and `rustc`; rustup selects the host target automatically:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
. "$HOME/.cargo/env"
rustup toolchain install stable
rustup default stable
rustc --version
cargo --version
```

Platform build dependencies:

- Ubuntu/Debian Linux: `sudo apt update`, then
  `sudo apt install build-essential pkg-config libgtk-3-dev
  libayatana-appindicator3-dev libglib2.0-dev libxdo-dev libx11-dev
  libnotify-bin`. `libnotify-bin` provides `notify-send` for for-os OS
  notifications.
- macOS: `xcode-select --install` for the Xcode command-line tools, plus the
  Rust stable toolchain above.
- Windows: Visual Studio Build Tools with the **Desktop development with C++**
  workload, plus Rust stable installed with the MSVC host toolchain.

Build and install the compiled addon from this repository root:

```bash
npm run for-os:install:required
```

This verifies the vendored source pin, runs `cargo build --release --locked`,
records a hash and toolchain versions in `build-manifest.json`, and copies the
verified addon to `node_modules/tray-icon-node`. To compile without
materializing it, use `npm run for-os:build`.

Run the Rust crate test target and the real Rust-to-TypeScript desktop
integration check:

```bash
npm run for-os:test:rust
npm run for-os:integration
```

The interactive integration check requires an active desktop session with a
system-tray host. It asks the operator to click **Search now**, **Accept
appointment**, and **Quit**, then verifies that each native menu event reached
the TypeScript adapter. The per-action timeout defaults to 90 seconds and can
be changed with `VOICE_TRAY_TEST_TIMEOUT_MS`. For a non-interactive real
tray create/update/dispose check, run
`npm run for-os:integration -- --smoke`; this also sends a test OS
notification from Rust and requires a graphical
desktop session.

## Why build at install (and the SAA-1290 disposition)

Building from the audited source on each platform removes the need for
per-platform prebuilt artifacts and therefore folds the previously separate
"darwin prebuild" follow-up (SAA-1290) into this rework: macOS is built from the
same vendored source as Linux and Windows, with no extra binary pin to obtain or
trust. The trade-off is a toolchain requirement on machines that want the tray
indicator; machines without it keep the graceful no-tray degradation.

## Integrity manifest

`source-manifest.json` pins every vendored source/wrapper file by SHA-512 and
records the upstream pin and the source-tree digest. It is generated by
`npm run for-os:integrity:record`; the corresponding embedded pins live in
`scripts/for-os-integrity.mjs`.

A successful build writes `build-manifest.json` next to the binary with the
source-tree digest, target triple, cargo/rustc versions, and the built binary's
SHA-512. `verifyVendoredTrayIntegrity()` verifies the pinned source tree and then
requires the binary to match that build manifest before the module is imported.

## Source and dependency audit notes (SAA-1292)

Reviewed the vendored Rust/Node source at the pinned commit:

- No network access (`reqwest`, sockets, HTTP clients), no subprocess spawning
  (`std::process`, `Command`), no environment-variable reads, and no dynamic
  code loading anywhere in `src/*.rs` or `build.rs`.
- Filesystem access is limited to `Icon::from_path`, which delegates decoding to
  the `image` crate for the icon path supplied by the caller.
- `unsafe` appears in exactly two places: the Win32 `PeekMessageW` pump in
  `src/lib.rs` (the documented message-loop handoff) and the `Send`/`Sync`
  impls for `AnyMenuItem` in `src/menu.rs`. Both are confined to the platform
  glue the tray library requires.
- Accepted residual (SAA-1297 F4, LOW, soundness): the `Send`/`Sync` impls rest
  on a partially argued thread-safety claim about tray-icon/muda handles; this
  integration is single-threaded (channel-polled events) and has no current
  trigger, and the upstream thread-safety question is noted here rather than
  blocking the vendored lane.
- Direct cargo dependencies: `napi` (resolves to 3.15.0), `napi-derive`
  (3.6.13), `tray-icon` 0.21.3, `image` 0.25.10, Linux-only `gtk` 0.18.2,
  Windows-only `windows-sys` 0.52, and build-dependency `napi-build` 2.6.0.
  `Cargo.lock` pins the full closure (244 packages). `native supply-chain workflow`
  scans that lockfile with osv-scanner every week and on changes.
